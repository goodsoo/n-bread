# Flow: 정산 (N빵)

**Defined:** 2026-06-04 · **Author:** UX 담당자(high-level) → AI(structure) · **Status:** Verified (구조 결정 3건 사용자 확정 후 구현·브라우저 검증 완료)
**App:** n-bread · **Stack:** React Router 6 코드 내 `<Route>` (`src/App.jsx`) · 상태 라이브러리 없음(컴포넌트 로컬 useState) · 데이터 `src/lib/share.js`(URL `?d=` + localStorage draft) + `src/lib/settle.js`(순수 계산)

<intent>
## 왜 이 flow

정산 도구의 가치는 "입력 → 답"이 빠른 것. 2026-06 점검에서 (1) 인원 스테퍼와 이름 리스트가 같은 정보를 두 번 입력시키고, (2) 지난 draft 무조건 복원이 새 정산 의도와 충돌하고, (3) 입력 실수(빈 금액)가 성공 화면("엔빵 완료!")으로 표현되는 문제를 확인. 이 문서는 그 셋을 제거한 흐름의 계약이다.
</intent>

<flow>
## Happy path

1. **홈** — 사용자: [N빵하기] 탭 → 시스템: 입력 화면 (유지 결정: 브랜드 + 공유 링크 수신자의 맥락 진입점)
2. **사람 입력** — 사용자: 이름 행 추가/삭제·이름 입력(선택) → 시스템: 인원수는 리스트 길이로 표시 (스테퍼 제거 결정)
3. **결제 입력** — 사용자: 결제마다 누가 냈나·얼마·누구 몫인지 → 시스템: 칩 토글로 N빵 대상 표시
4. **정산하기** — 사용자: 버튼 탭 → 시스템: 금액 합 0 이면 제출 차단 + 안내, 아니면 결과로
5. **결과** — 시스템: 송금 흐름(누가→누구, 얼마) + 각자 요약 + 올림 안내 → 사용자: 링크 복사 or 수정
</flow>

<screens>
## 화면

### 홈 (`/`)
- **상태**: 정상만 · **진입**: 직접 / 로고 탭 · **이탈**: /calculation, /about
- **카피**: 유지 ("여러 명이 결제해도 한 번의 송금으로")

### 정보 입력 (`/calculation`)
- **상태**: 깨끗한 초기(2명) / 복원 배너(draft 존재 시) / 한계 에러(2명 미만·20명 초과 시도)
- **진입**: 홈, 결과의 [수정하기] · **이탈**: /result (검증 통과 시만)
- **구성**: ① 복원 배너(조건부) ② "누가 함께했나요?" 카드 — 이름 행 + 행별 ✕ + [＋ 사람 추가] ③ 결제 카드들 — 누가 냈나요(select)/얼마였나요(금액)/누구끼리 N빵하나요(칩) ④ [＋ 결제 추가] ⑤ [정산하기]
- **카피**: 제목 "누가 얼마 냈나요?" · 배너 "지난 정산이 남아 있어요 — [이어하기] [새로 시작]" · 제출 차단 "결제 금액을 입력해 주세요." · 한계 "혼자서 정산을..?" / "죄송해요, 20명까지만 지원해요."

### 정산 결과 (`/result?d=`)
- **상태**: 정상 / 진짜 0원 정산(금액 있는데 잔액 전부 0) / 데이터 없음(?d 누락·손상)
- **진입**: 정산하기, 공유 URL · **이탈**: /calculation (수정), 링크 복사
- **카피**: 제목 "정산 결과" (송금 전이므로 "완료" 아님) · 송금 섹션 "이렇게 보내면 끝나요 — 송금 N번" · 요약 섹션 "각자 부담 정리" · 올림 발생 시 "나누어 떨어지지 않는 금액은 올림했어요. 남는 돈은 결제한 사람이 받아요." · 진짜 0원 "정산할 게 없네요! 이렇게 깔끔할 수가!" · 데이터 없음 "정산할 내용을 찾지 못했어요."

<edge-cases>
## 엣지케이스

- **사람 삭제 시 참조**: 삭제된 사람이 결제자면 사람1로, 뒤 인덱스 결제자는 −1 재매핑. joins 도 해당 인덱스 제거, 전부 꺼지면 첫 사람 켬.
- **빈 금액 제출**: 차단 + "결제 금액을 입력해 주세요." (결과 화면으로 안 보냄)
- **공유 URL 로 빈 데이터 진입**: 결과 화면에서 "정산할 금액이 없어요" — 성공 문구 금지
- **KO 입력(IME)**: 이름 입력은 조합 중 상태 그대로 저장 (controlled input, 변환 강제 없음)
- **draft 손상**: `loadDraft()` null 반환 → 배너 미표시, 깨끗한 시작
</edge-cases>
